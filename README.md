# Cheapest Trip — парсер самых дешёвых поездок

> Don't choose where to go. Let the algorithm find the cheapest real trip you can take.

Сервис ищет **самую дешёвую полноценную поездку**, а не самый дешёвый билет:

```
TOTAL TRIP COST = перелёт туда + перелёт обратно + отель + обязательные сборы
```

Пользователь задаёт условия (или пишет их обычным текстом), сервис сам выбирает направление, даты,
аэропорты, маршруты туда и обратно (независимо друг от друга, с любым числом пересадок, которое
возвращает провайдер) и сортирует результаты по полной стоимости.

**Только реальные данные.** Ни один рейс, цена, отель или ссылка не придумываются. Если источника
нет, сервис так и пишет: `Flight provider connection required` / `Hotel provider connection required`.

## Быстрый старт

```bash
pip install -r requirements.txt
# впишите токен в .env (см. ниже)
python run.py            # откроется http://127.0.0.1:8770
```

### Как получить токен Travelpayouts (Aviasales), это бесплатно

1. Зарегистрируйтесь на <https://www.travelpayouts.com/> (email и пароль, сайт указывать не обязательно).
2. В личном кабинете откройте каталог программ, найдите **Aviasales** и подключитесь к программе.
3. Скопируйте **API-токен** в разделе кабинета, посвящённом API: обычно это «Профиль → API-токен»
   или «Инструменты → API». Названия пунктов меню у Travelpayouts иногда меняются.
4. Вставьте его в `.env`:
   ```
   TRAVELPAYOUTS_TOKEN=ваш_токен
   ```
   Там же можно указать `TRAVELPAYOUTS_MARKER`, ваш партнёрский ID для ссылок (необязательно).
5. Перезапустите `python run.py`. Вверху страницы должно появиться «✈️ Aviasales: подключён».

Файл `.env` в git не попадает (см. `.gitignore`).

## Что умеет

- **🔎 Find me the cheapest trip**: главный результат ✈️ + 🏨 CHEAPEST TRIP (туда, обратно, отель,
  TOTAL, время проверки цены, кнопки VIEW FLIGHT / VIEW RETURN FLIGHT / VIEW HOTEL), другие даты
  для лучшего направления, Other cheap destinations, таблица сравнения с сортировкой по любой колонке.
- **🌍 Where can I travel cheapest?**: список реальных направлений, найденных поиском, по возрастанию Total.
- **Запрос обычным языком**: «Хочу из России куда-нибудь в Азию на 5 дней в течение ближайших 3 месяцев,
  перелёт максимум 25 000 рублей, отель максимум $40». Форма заполняется автоматически,
  а каждое допущение показывается отдельным пунктом.
- **FROM / TO**: город, аэропорт (`DME`), страна (`Russia`, `Таиланд`), регион по стандарту ООН
  (`Europe`, `Азия`, `Юго-Восточная Азия`), часть России (`Европейская часть России` западнее
  Урала, `Азиатская часть России`), `Anywhere` или **список через запятую** (`Москва, Казань, Сочи`).
  Понимает падежи («из Москвы», «в Турцию») и разговорные названия («Питер», «Бали», «РФ»).
- **Исключения** (поля «Кроме» в форме или текстом): «куда угодно, но не в Минск», «кроме Турции
  и Египта», «без Беларуси», «из России, кроме Москвы и Питера», «из любой страны кроме России».
  Исключение относится к тому, о чём шла речь: после «куда угодно» — к направлениям, после
  «из России» — к городам вылета. «Не из…» всегда про вылет, «не в…» всегда про направление.
  Исключённые города вылета не тратят лимит `MAX_ORIGIN_CITIES`.
- **WHEN**: Anytime (ближайшие N месяцев, задаётся в `.env`), 1/3/6/12 месяцев, конкретный месяц, окно дат вылета.
- **TRIP LENGTH**: 1–14 ночей, диапазон (3–7 проверяет 3, 4, 5, 6 и 7) или Flexible.
  Более короткая поездка не считается автоматически более дешёвой.
- **Бюджеты**: на перелёт (по умолчанию **No limit**), на отель за ночь, на всю поездку.
  Опция **Show options above budget** показывает варианты дороже бюджета с пометкой
  `Above your budget` и только после вариантов в рамках бюджета. Молча бюджет не нарушается.
- **Пересадки** без искусственного лимита, `3 STOPS` и `4 STOPS` выделены заметно. Есть фильтр, если нужен.
- **Предупреждения**: разные аэропорты прилёта и обратного вылета (IST → SAW), ночной прилёт,
  ранний обратный вылет, туда и обратно — два отдельных билета.
- **«Тёплое место»**: реальные температуры в эти же даты год назад (Open-Meteo, ERA5).
- **Валюты**: всё приводится к выбранной валюте по официальному курсу ЦБ РФ. Курс, источник и время
  получения видны в блоке «Как искали».

## Бесплатная публикация на Render

Нужны аккаунты GitHub и Render (без карты). В `.env` впишите `DEPLOY_GITHUB_TOKEN`
(classic-токен GitHub с правами `repo` и `gist`) и `RENDER_API_KEY` (Render → Account Settings →
API Keys), затем из папки проекта:

```bash
python deploy/render_setup.py
```

Скрипт выкладывает код в закрытый репозиторий `<логин>/cheapest-trip` (без `.env`, баз и кэша),
создаёт сервис Render (бесплатный тариф, Docker, Франкфурт) с настройками из `.env` и ждёт запуска.
Повторный запуск — обновление сайта (или просто `git push`: Render пересоберёт сам).

Особенности бесплатного тарифа и как они закрыты:

- **Сон через 15 минут без посетителей** (вместе с ним встали бы монитор цен и Telegram-бот).
  На Render сайт сам заходит на свой адрес раз в `KEEP_AWAKE_MINUTES` (10) минут. Бесплатных
  750 часов в месяц хватает на круглосуточную работу одного сайта.
- **Диск стирается при каждом перезапуске и обновлении.** Отслеживаемые 📌 билеты и привязки
  Telegram раз в `BACKUP_EVERY_MINUTES` (5) минут и при остановке копируются в секретный GitHub
  Gist (`BACKUP_GIST_ID`, `BACKUP_GITHUB_TOKEN`) и восстанавливаются при старте.
- **Слабый процессор (0,1 ядра):** поиск медленнее, монитор делает до 10 запросов за цикл.

## Публикация на VPS (Ubuntu 22.04/24.04)

Нужен сервер с публичным IPv4 и SSH-ключом `~/.ssh/cheaptrip_vps` (его открытая часть
добавляется при создании сервера). Из папки проекта в Git Bash:

```bash
bash deploy/deploy_vps.sh <IP-сервера> [логин]      # логин по умолчанию root
```

Сайт и HTTPS стартуют сами при включении ВМ. Если после остановки ВМ сменился публичный IP,
запустите скрипт с новым IP — он переключит HTTPS на новый адрес `<IP-через-дефисы>.sslip.io`.

Первый запуск настраивает сервер (`deploy/setup_server.sh`: Python, служба `cheaptrip` с
автозапуском, Caddy с HTTPS от Let's Encrypt, файрвол), затем заливает код и `.env`
(доступен только служебному пользователю) и перезапускает сайт. Повторный запуск — обновление.
Адрес: `https://<IP-через-дефисы>.sslip.io` (sslip.io бесплатно превращает IP в домен), а также `http://<IP>`.

Сайт открыт всем, поэтому поиски нормируются: `MAX_CONCURRENT_SEARCHES` одновременно на сервере,
`SEARCHES_PER_IP_PER_HOUR` в час и один поиск за раз с одного адреса. Каждый посетитель видит
мониторинг только своих билетов; 📌 хранятся в его браузере.

## Мониторинг цен каждые 10 секунд

После каждого поиска билеты найденных направлений (туда и обратно) попадают в базу
`cheaptrip/data/trips.db` (SQLite). Фоновый монитор внутри сервера каждые `WATCH_INTERVAL_SECONDS`
заново запрашивает их у Aviasales в обход кэша и записывает:

- текущую цену и дату, когда её видели на Aviasales;
- изменения: ▲ подорожал / ▼ подешевел / 🔴 пропал (плюс самый дешёвый билет в тот же день) / вернулся.

На странице у каждого билета живая строка статуса, итог поездки пересчитывается сам, внизу —
таблица всей базы. Кнопка **📌 Следить постоянно** оставляет поездку в базе после следующих поисков
(без неё новый поиск заменяет список отслеживаемых).

Один запрос проверяет все отслеживаемые билеты на одном маршруте в один день. Если рейсов-дней
больше `WATCH_MAX_REQUESTS`, они проверяются по кругу: сначала закреплённые, потом давно не проверенные.
Во время большого поиска монитор ждёт, чтобы вместе они не превысили лимит 600 запросов в минуту.

Честная граница: «в продаже» значит «есть в данных Aviasales». Aviasales обновляет эти данные,
когда кто-то ищет рейс у них на сайте. Монитор ловит обновление в течение 10 секунд, но живую
проверку мест делает только страница бронирования.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `WATCH_INTERVAL_SECONDS` | 10 | период сверки |
| `WATCH_AUTO_TOP` | 20 | сколько направлений последнего поиска отслеживать |
| `WATCH_MAX_REQUESTS` | 50 | запросов за цикл (50 за 10 с = 300 в минуту из 600) |
| `PRICE_MAX_AGE_DAYS` | 2 | фильтр свежести цен в поиске (в форме: «Свежесть цены») |

### Уведомления в Telegram

1. Создайте бота: в Telegram напишите **@BotFather** → `/newbot` → имя → логин на `bot`.
   BotFather пришлёт токен вида `123456:ABC…`.
2. Впишите его в `.env`: `TELEGRAM_BOT_TOKEN=…` и перезапустите сервер.

У поездки на сайте появится кнопка **🔔 Уведомления в Telegram**. Она открывает бота со
случайным кодом этого браузера; после «Старт» бот связывает браузер с чатом. Дальше бот пишет,
когда у билетов, отслеживаемых в этом браузере (📌), меняется цена, они пропадают из данных
Aviasales или возвращаются. Команды бота: `/list` — отслеживаемые билеты, `/stop` — отключить.

- Сообщается только то, что монитор реально увидел; изменения нескольких билетов идут одним сообщением.
- Защита от «мигания» кэша: новое состояние должно продержаться `TELEGRAM_CONFIRM_SECONDS` (60 с),
  и по одному билету — не чаще раза в `TELEGRAM_MIN_INTERVAL_MINUTES` (5 мин); если цена за это
  время вернулась к прежней, сообщения не будет.
- Копия на компьютере получает сообщения боту сама (long polling). Копия на сервере — по webhook:
  `deploy_vps.sh` записывает ей `PUBLIC_URL` в `.env.server`. Пока у бота стоит webhook сервера,
  локальная копия кнопку не показывает, чтобы не перехватывать чужие подключения.

## Как работает поиск

`cheaptrip/search.py` → `CheapTripSearchService`:

| Стадия | Что делает |
|---|---|
| UNDERSTAND | места, даты, длительность, бюджеты; ошибки ввода сразу понятным текстом |
| DISCOVERY | дешёвые реальные билеты в одну сторону по каждому городу вылета и месяцу; куда лететь, решает провайдер, а не список стран |
| CANDIDATES | самые перспективные направления (и климат, если просили тёплое) |
| ROUTES | полные календари туда и обратно, все маршруты, которые вернул провайдер |
| COMBINE | независимое сочетание туда + обратно для каждого числа ночей, проверка стыковки по времени и часовым поясам |
| HOTELS | отели только для оставшихся направлений и дат |
| TOTAL | перелёт + отель + обязательные сборы в валюте пользователя, бюджеты |
| REVALIDATE | повторный запрос лучших вариантов мимо кэша; пропавшие билеты убираются |
| RANK | сортировка по `tripTotal ASC` |

Полный перебор «направления × даты × длительности × рейсы × отели» сжёг бы лимит API, поэтому поиск
многоступенчатый. Все ограничения глубины задаются в `.env` и показываются в результате
(«Проверено 25 из 105 городов вылета…»):

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `MAX_ORIGIN_CITIES` | 25 | сколько городов вылета проверять для страны или региона (по числу реальных маршрутов) |
| `MAX_CANDIDATE_DESTINATIONS` | 20 | сколько направлений разбирать глубоко |
| `MAX_ORIGINS_PER_DESTINATION` | 2 | сколько самых дешёвых городов вылета на направление |
| `REVALIDATE_TOP` | 5 | сколько лучших вариантов перепроверять |
| `DEFAULT_SEARCH_MONTHS` | 3 | горизонт для Anytime |
| `FLEXIBLE_NIGHTS_MIN/MAX` | 2 / 30 | доступная длительность поездки (ночей) и диапазон Flexible |
| `API_CACHE_MINUTES` | 60 | локальный кэш ответов API; время проверки цены берётся из кэша честно |

## Ограничения провайдеров (честно)

- **Aviasales Data API** отдаёт кэш цен из реальных поисков пользователей Aviasales за последние
  ~48 часов, а не живой поиск мест. Итоговую цену и наличие подтверждает страница бронирования.
  Лучшие варианты перед показом перепроверяются. Цена указана за 1 взрослого, эконом.
- API **не отдаёт сегменты**: города пересадок, смену аэропорта внутри маршрута и self-transfer.
  Число пересадок известно. Поля `segments`, `isSelfTransfer`, `airportChange` в модели есть, и
  провайдер с такими данными (например, живой Aviasales Flight Search API) заполнит их без изменений UI.
- **Отели — Xotelo / TripAdvisor** (`HOTEL_PROVIDER=xotelo`, бесплатно, без ключа). Цена отеля на
  конкретные даты берётся из сравнения TripAdvisor: Booking.com, Trip.com, Agoda, Expedia и др.;
  показывается самая низкая и на каком сайте. Ограничения:
  - код города в TripAdvisor берётся из проверенного справочника `cheaptrip/data/tripadvisor_geo_seed.json`
    (59 популярных направлений) или из Wikidata; каждый код проверяется по координатам отелей. Нет кода —
    «Hotel data unavailable». `RAPIDAPI_KEY` включает поиск города по названию и закрывает пробелы;
  - в некоторых странах (например, Беларусь) сайты-продавцы не работают — цен нет, поездка остаётся в
    выдаче с пометкой «без отеля»;
  - завтрак источник не сообщает; хостел может означать место в общем номере (фильтр «Private room»
    хостелы исключает);
  - цены отелей проверяются для `HOTEL_MAX_DESTINATIONS` направлений с самыми дешёвыми перелётами
    (по 2 варианта дат); поездки с реальным отелем идут в выдаче первыми, без отеля — ниже.
  Официальный Trip.com (`HOTEL_PROVIDER=tripcom`) ждёт партнёрского доступа.

## Структура

```
cheaptrip/
  config.py            настройки из .env
  models.py            TripQuery, FlightOption, HotelOffer, TripResult, SearchReport
  geo.py               города/аэропорты/страны (Travelpayouts) + регионы ООН, разбор названий
  search.py            CheapTripSearchService — оптимизация TOTAL TRIP COST
  nlp.py               текст → TripQuery
  fx.py                курсы ЦБ РФ
  weather.py           климат (Open-Meteo)
  http.py              кэш, лимиты, ретраи при 429
  providers/
    base.py            FlightProvider, HotelProvider (searchHotels)
    aviasales.py       AviasalesProvider
    tripcom.py         TripComProvider (ожидает партнёрский доступ)
  api.py               FastAPI
web/index.html         интерфейс
tests/                 тесты логики (фейковые провайдеры живут только здесь)
```

### Новый источник отелей (Booking, Agoda, Expedia…)

Реализуйте `HotelProvider.searchHotels(destination, checkIn, checkOut, maxPricePerNight, …)` →
`HotelSearchResult` с реальными `HotelOffer` (цена, валюта, обязательные сборы в `fees`, ссылка,
`checked_at`) и подставьте класс в `cheaptrip/api.py`. Поиск, фильтры, итог и интерфейс заработают сами.

## Тесты

```bash
python -m pytest
```

Проверяются сценарии из ТЗ:
- дорогой отель переворачивает выбор, хотя билет дешевле;
- туда и обратно выбираются независимо: 7 500 + 6 800 = 14 300;
- маршрут с 4 пересадками выбирается, если он самый дешёвый;
- бюджет и Above your budget; No limit действительно без лимита;
- ночной прилёт сдвигает заезд;
- длинная поездка может оказаться дешевле короткой;
- исчезнувший при перепроверке билет убирается;
- нет отеля под условия — направления нет в выдаче;
- разбор примеров запросов из ТЗ.
